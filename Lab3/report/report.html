Lab 3: Parallel Sieve of Eratosthenes

Adomas Vensas, student ID 2525104. Problem 4. Written in C# (.NET 8) with threads.

1. Problem

Find all prime numbers up to N with the Sieve of Eratosthenes: take 2 and cross out all its multiples, then take the next number that is not crossed out and do the same, and so on. The numbers that are left are primes. My program counts them.

2. How I parallelized it

  • Dividing the work: first one thread finds the small primes up to √N (this is very fast). Then the numbers up to N are split into equal parts (segments). Each part can be sieved on its own using the small primes.
  • Giving parts to threads: there is a shared counter that shows which part is next. When a thread is free, it takes the next part and increases the counter. So faster threads just take more parts.
  • Synchronization: the counter and the total are changed with atomic Interlocked operations. The main thread waits for all threads with Join.

3. Experiment

4. Conclusions

  • Maximum speedup: 15.6 times with 24 threads (N = 109): from 1439 ms to 92 ms.
  • How good it is: almost linear up to 8 threads, very good with 16 threads (13 times), good with 24 threads. For small N (107) the speedup is small (3.7 times), because the program finishes in a few milliseconds.
  • Why it is not perfect: creating threads takes some time, at the end some threads wait for the last parts, all cores share the same memory, and the procesor runs a bit slower when all cores are busy.
  • Is it scalable: yes, for big N. The bigger N is, the better the speedup (3.7, 9.4 and 15.6 with 24 threads). Part size also matters: 64K–1M works best. Too small parts add extra work, too big parts do not fit in the cache and there are too few of them to share between threads.
